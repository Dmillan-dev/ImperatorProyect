# 10 — Risks and Assumptions

## Critical Assumptions

1. Cross-platform traceability pain is real and urgent.
2. Technical buyers accept a neutral intelligence layer.
3. Operational value can be demonstrated via measurable KPIs.
4. AI governance and compliance pressure will continue rising.
5. Customers can provide enough usage/value signals to estimate decision-level ROI.
6. The narrow AI/cloud spend recovery wedge produces credible savings in a pilot.

## Main Risks

- category-creation friction
- perceived integration complexity
- long enterprise sales cycles
- adjacent tool overlap
- weak or unavailable value signals for ROI estimation
- over-expanding beyond the four MVP integration domains
- overbuilding platform surfaces before one paid workflow is proven
- starting with too many recommendation families
- premature microservice, graph, vector, broker or SDK work
- treating AI recommendations as autonomous execution instead of approval-ready decisions

## Mitigations

- narrow, high-pain wedge first
- “augment, not replace” positioning
- KPI-led value demonstration
- team-by-team land-and-expand adoption
- validate one complete Jira -> GitHub -> AWS -> OpenAI + Anthropic Claude decision before expanding systems
- validate the AI/cloud spend recovery wedge before negative-ROI feature or duplicate-service analysis
- keep Phase 1 architecture simple until repeated customer demand justifies service separation
- sell recommendations as evidence-backed approvals, not autonomous changes
