# 11 — Validation Plan 30/60/90

## Days 0–30: Validate Problem and Priority

- interview CTO / VP Engineering, Platform Engineering and CFO/FinOps profiles
- validate whether they can currently reconstruct Jira → GitHub → AWS → OpenAI/Azure OpenAI for one decision
- identify one recent feature, AI workflow or infrastructure change with visible cost
- capture customer language for "decision ROI", "waste", "ownership", "usage" and "approval"

## Days 31–60: Validate Narrative and Solution Framing

- test the message: "One Decision. One Timeline. One ROI."
- validate the four information domains: Business Context, Code & Deployment, Infrastructure & Cost, AI Consumption
- compare buyer response to "MTTR reduction" vs "live ROI of a shipped decision"
- refine the dashboard question: "This decision costs X today, creates Y estimated value, and can recover Z per year."

## Days 61–90: Validate Commercial Viability

- run a manual concierge reconstruction of 2–3 real customer decisions
- estimate current monthly cost, usage signal and annualized recovery opportunity
- validate whether CFO/FinOps joins the buying path when ROI is shown
- decide readiness for Phase 1 product design around GitHub, AWS, Jira and OpenAI/Azure OpenAI

## Go/No-Go Criteria

Go if all are true:
- customers recognize the four-system reconstruction as painful and recurring,
- at least one buyer cares about decision-level ROI enough to sponsor a pilot,
- the four-domain MVP can produce a credible recommendation without broad connector coverage,
- value can be tied to explicit assumptions and measurable KPIs,
- the buyer path includes both technical ownership and economic validation.
