# Guía de publicación de IMPERATOR en LinkedIn

## 1. Perfil desde el que publicar

Publica desde tu perfil personal. En esta fase la historia relevante es la de
un estudiante y creador que busca contrastar un problema profesional. Una
página corporativa sin audiencia reduciría el alcance y haría que la petición
pareciese más comercial.

Titular recomendado:

> Estudiante DAM | Arquitectura de Software | Creador de IMPERATOR, sistema de inteligencia para decisiones operativas

Texto breve para la sección Acerca de:

> Estoy desarrollando IMPERATOR como TFG: una plataforma que relaciona evidencia operativa, decisiones humanas y valor económico verificable. Actualmente busco profesionales de Engineering, Platform, Cloud, FinOps y Security para validar el problema mediante entrevistas breves.

## 2. Qué publicar primero

Usa `IMPERATOR_Discovery_Deck_ES.pdf` como documento de LinkedIn. El carrusel
permite que el lector avance por el problema y vea una superficie de producto
sin salir de la publicación.

Nombre recomendado del documento:

> IMPERATOR - De evidencia operativa a valor verificable

Utiliza el texto de `LinkedIn_Publicacion_ES.md` como cuerpo. No añadas un
enlace externo en la primera publicación. La única llamada a la acción debe ser
responder o enviar un mensaje directo.

## 3. Secuencia de publicación

1. Día 1: publica el carrusel con la solicitud de entrevistas.
2. Durante las primeras 24 horas: responde personalmente a cada comentario.
3. Día 2-4: envía un mensaje privado a contactos relevantes que hayan mostrado interés.
4. Semana 2: publica una reflexión anonimizada con los primeros patrones encontrados.
5. Después de 8-10 entrevistas: publica una encuesta para cuantificar esos patrones.

No publiques el PDF, el vídeo y cinco capturas como publicaciones separadas el
mismo día. Compiten entre sí y diluyen la llamada a la entrevista.

## 4. Mensaje directo después de una reacción

> Hola, [Nombre]. Gracias por reaccionar a la publicación de IMPERATOR. Estoy contrastando cómo las empresas reconstruyen decisiones operativas y su impacto económico. ¿Te vendría bien una conversación de 15-20 minutos la próxima semana? No necesito acceso a sistemas ni información confidencial.

## 5. Qué preguntar en la entrevista

1. Cuéntame una decisión operativa reciente que tuviera impacto económico.
2. ¿Qué evidencia se consultó antes de decidir?
3. ¿Quién tuvo autoridad para aprobarla?
4. ¿Dónde quedó registrado el motivo?
5. ¿Pudisteis comprobar después si produjo el resultado esperado?
6. ¿Qué parte fue más lenta o difícil?
7. ¿Sería suficientemente importante como para pagar por resolverla?

No enseñes el carrusel durante los primeros minutos. Primero descubre cómo
describe la persona el problema con sus propias palabras. Enseña IMPERATOR solo
cuando exista un caso concreto con el que compararlo.

## 6. Métrica comercial

Registra el embudo, no solo el número de contactos:

```text
Contacto
-> Conversación
-> Problema confirmado
-> Caso concreto identificado
-> Responsable identificado
-> Datos potencialmente disponibles
-> Interés en piloto
-> Design partner
```

Objetivo inicial: 10-15 entrevistas, tres problemas recurrentes y un posible
design partner cualificado.

## 7. Límites de comunicación

Puedes decir:

- caso sintético y arquitectura funcional;
- GitHub y AWS como fuentes de Evidence;
- recomendación y ROI deterministas;
- aprobación humana y Ledger append-only;
- `19.440 EUR/año` como estimación canónica del caso de prueba.

No puedes decir:

- que IMPERATOR ha ahorrado dinero a un cliente;
- que el valor realizado actual es `18.960 EUR`;
- que el runtime Docker está completamente certificado;
- que existe un piloto conectado a datos reales;
- que Jira, OpenAI o Claude están integrados en el MVP actual;
- que IMPERATOR está listo para producción.
